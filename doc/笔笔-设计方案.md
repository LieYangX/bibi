## 1. 技术栈选型

### 1.1 技术栈总览

| 层级      | 技术选型                | 版本       | 说明                                     |
| --------- | ----------------------- | ---------- | ---------------------------------------- |
| 桌面框架  | Electron                | 最新稳定版 | 跨平台桌面应用容器                       |
| 构建工具  | electron-vite           | v5.x       | 基于 Vite 的 Electron 构建工具，支持 HMR |
| UI 框架   | Vue 3                   | 3.5+       | Composition API + `<script setup>`       |
| UI 组件库 | Arco Design Vue         | 2.x        | 企业级 UI 组件库                         |
| 状态管理  | Pinia                   | 2.x        | Vue 3 官方状态管理                       |
| 路由      | Vue Router 4            | 4.x        | 渲染进程路由                             |
| 数据库    | SQLite (better-sqlite3) | 最新版     | 嵌入式数据库，零配置                     |
| ORM       | Drizzle ORM             | 最新版     | 轻量级类型安全 ORM                       |
| 语言      | TypeScript              | 5.x        | 全栈类型安全                             |
| 打包分发  | electron-builder        | 最新版     | 打包为 Windows 安装包                    |
| 代码规范  | ESLint + Prettier       | -          | 统一代码风格                             |

### 1.2 选型理由

| 选型                | 理由                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------- |
| **electron-vite**   | 比原生 Electron + Webpack 配置简单数倍，主进程/预加载/渲染进程三合一配置，HMR 开发体验好 |
| **Arco Design Vue** | 字节跳动出品，组件齐全，文档中文友好，相比 Element Plus 更现代                           |
| **better-sqlite3**  | 同步 API（更简单）、性能优秀、与 Electron 原生模块兼容良好                               |
| **Drizzle ORM**     | 相比 TypeORM 更轻量，相比 Prisma 不需要额外引擎，类型推断优秀，适合 Electron 场景        |

## 3. 数据库设计

### 3.1 ER 关系概览

```
users (1) ──── (N) accounts
users (1) ──── (N) transactions
users (1) ──── (N) categories
users (1) ──── (N) budgets

accounts (1) ──── (N) transactions  (作为交易账户)
accounts (1) ──── (N) transactions  (作为转账目标账户)

categories (1) ──── (N) sub_categories
categories (1) ──── (N) budgets
categories (1) ──── (N) transactions
```

### 3.2 表结构

#### 3.2.1 users（用户表）

| 字段名     | 类型           | 约束     | 说明                   |
| ---------- | -------------- | -------- | ---------------------- |
| id         | TEXT (UUID)    | PK       | 用户唯一标识           |
| name       | TEXT           | NOT NULL | 用户名                 |
| color      | TEXT           | NOT NULL | 主题色标识（十六进制） |
| created_at | TEXT (ISO8601) | NOT NULL | 创建时间               |
| updated_at | TEXT (ISO8601) | NOT NULL | 最后修改时间           |

#### 3.2.2 accounts（账户表）

| 字段名          | 类型        | 约束                    | 说明                                       |
| --------------- | ----------- | ----------------------- | ------------------------------------------ |
| id              | TEXT (UUID) | PK                      | 账户唯一标识                               |
| user_id         | TEXT (UUID) | FK → users.id, NOT NULL | 所属用户                                   |
| name            | TEXT        | NOT NULL                | 账户名称（如工资卡）                       |
| type            | TEXT        | NOT NULL                | 类型：bank/wechat/alipay/cash/credit/other |
| initial_balance | REAL        | NOT NULL, DEFAULT 0     | 初始余额                                   |
| balance         | REAL        | NOT NULL, DEFAULT 0     | 当前余额（由系统自动计算）                 |
| sort_order      | INTEGER     | NOT NULL, DEFAULT 0     | 排序序号                                   |
| is_hidden       | INTEGER     | NOT NULL, DEFAULT 0     | 是否隐藏：0=显示, 1=隐藏                   |
| created_at      | TEXT        | NOT NULL                | 创建时间                                   |
| updated_at      | TEXT        | NOT NULL                | 最后修改时间                               |

#### 3.2.3 categories（一级分类表）

| 字段名     | 类型        | 约束                    | 说明                 |
| ---------- | ----------- | ----------------------- | -------------------- |
| id         | TEXT (UUID) | PK                      | 分类唯一标识         |
| user_id    | TEXT (UUID) | FK → users.id, NOT NULL | 所属用户             |
| name       | TEXT        | NOT NULL                | 分类名称             |
| type       | TEXT        | NOT NULL                | 类型：expense/income |

#### 3.2.4 sub_categories（二级分类表）

| 字段名      | 类型        | 约束                         | 说明           |
| ----------- | ----------- | ---------------------------- | -------------- |
| id          | TEXT (UUID) | PK                           | 子分类唯一标识 |
| category_id | TEXT (UUID) | FK → categories.id, NOT NULL | 所属一级分类   |
| name        | TEXT        | NOT NULL                     | 子分类名称     |
| sort_order  | INTEGER     | NOT NULL, DEFAULT 0          | 排序序号       |
| created_at  | TEXT        | NOT NULL                     | 创建时间       |

#### 3.2.5 transactions（流水表）

| 字段名            | 类型           | 约束                         | 说明                                     |
| ----------------- | -------------- | ---------------------------- | ---------------------------------------- |
| id                | TEXT (UUID)    | PK                           | 流水唯一标识                             |
| user_id           | TEXT (UUID)    | FK → users.id, NOT NULL      | 所属用户                                 |
| type              | TEXT           | NOT NULL                     | 类型：expense/income/transfer/adjustment |
| account_id        | TEXT (UUID)    | FK → accounts.id, NOT NULL   | 发生账户                                 |
| target_account_id | TEXT (UUID)    | FK → accounts.id, NULL       | 目标账户（转账时必填）                   |
| category_id       | TEXT (UUID)    | FK → categories.id, NULL     | 一级分类（转账/调整可为空）              |
| sub_category_id   | TEXT (UUID)    | FK → sub_categories.id, NULL | 二级分类（可选）                         |
| amount            | REAL           | NOT NULL                     | 金额（支出记正数，收入记正数）           |
| date              | TEXT (ISO8601) | NOT NULL                     | 交易日期                                 |
| note              | TEXT           | NULL                         | 备注，最长 200 字                        |
| is_deleted        | INTEGER        | NOT NULL, DEFAULT 0          | 软删除标记：0=正常, 1=已删除             |
| created_at        | TEXT           | NOT NULL                     | 创建时间                                 |
| updated_at        | TEXT           | NOT NULL                     | 最后修改时间                             |

> **关于金额的说明**：支出和收入金额均存为正数，通过 `type` 字段区分方向。统计时根据 `type` 做正负处理。

#### 3.2.6 budgets（预算表）

| 字段名      | 类型        | 约束                     | 说明                  |
| ----------- | ----------- | ------------------------ | --------------------- |
| id          | TEXT (UUID) | PK                       | 预算唯一标识          |
| user_id     | TEXT (UUID) | FK → users.id, NOT NULL  | 所属用户              |
| category_id | TEXT (UUID) | FK → categories.id, NULL | 一级分类（空=总预算） |
| year        | INTEGER     | NOT NULL                 | 年份                  |
| month       | INTEGER     | NOT NULL                 | 月份                  |
| amount      | REAL        | NOT NULL                 | 预算金额              |
| created_at  | TEXT        | NOT NULL                 | 创建时间              |
| updated_at  | TEXT        | NOT NULL                 | 最后修改时间          |

> **复合唯一约束**：(user_id, category_id, year, month)，同一用户同一分类同一个月只能有一条预算。category_id 为空时表示月度总预算。

### 3.3 索引设计

| 表           | 索引字段               | 说明                        |
| ------------ | ---------------------- | --------------------------- |
| accounts     | (user_id)              | 按用户查询账户              |
| transactions | (user_id, date)        | 按用户+日期查流水（最常用） |
| transactions | (user_id, type)        | 按用户+类型筛选             |

### 3.4 Drizzle Schema 定义示例

以下为 Drizzle ORM 的核心 schema 定义参考：

```typescript
// src/main/database/schema/transaction.schema.ts
import { sqliteTable, text, real, integer } from 'drizzle-orm/sqlite-core'

export const transactions = sqliteTable('transactions', {
    id: text('id').primaryKey(),
    userId: text('user_id')
        .notNull()
        .references(() => users.id),
    type: text('type', {
        enum: ['expense', 'income', 'transfer', 'adjustment']

    accountId: text('account_id')

    targetAccountId: text('target_account_id').references(() => accounts.id),
    categoryId: text('category_id').references(() => categories.id),
    subCategoryId: text('sub_category_id').references(() => subCategories.id),
    amount: real('amount').notNull(),
    date: text('date').notNull(),
    note: text('note'),
    isDeleted: integer('is_deleted').notNull().default(0),
    createdAt: text('created_at').notNull(),
    updatedAt: text('updated_at').notNull()
```

## 4. IPC 接口设计

### 4.1 通信方式

使用 Electron 的 `contextBridge` + `ipcRenderer.invoke` / `ipcMain.handle` 模式（基于 Promise 的请求-响应模式）。

```typescript
// preload/index.ts — 暴露给渲染进程的 API
contextBridge.exposeInMainWorld('electronAPI', {
    // 用户
    user: {
        list: () => ipcRenderer.invoke('user:list'),
        create: (name: string) => ipcRenderer.invoke('user:create', name),
        switch: (id: string) => ipcRenderer.invoke('user:switch', id),
        delete: (id: string) => ipcRenderer.invoke('user:delete', id)
    },
    // 账户
    account: {
        list: () => ipcRenderer.invoke('account:list'),
        create: (data: CreateAccountDTO) => ipcRenderer.invoke('account:create', data),
        update: (id: string, data: UpdateAccountDTO) =>
            ipcRenderer.invoke('account:update', id, data),
        delete: (id: string) => ipcRenderer.invoke('account:delete', id)
    },
    // 分类
    category: {
        list: (type?: string) => ipcRenderer.invoke('category:list', type),
        create: (data: CreateCategoryDTO) => ipcRenderer.invoke('category:create', data),
        update: (id: string, data: UpdateCategoryDTO) =>
            ipcRenderer.invoke('category:update', id, data),
        delete: (id: string) => ipcRenderer.invoke('category:delete', id),
        resetDefaults: () => ipcRenderer.invoke('category:resetDefaults')
    },
    // 流水
    transaction: {
        create: (data: CreateTransactionDTO) => ipcRenderer.invoke('transaction:create', data),
        update: (id: string, data: UpdateTransactionDTO) =>
            ipcRenderer.invoke('transaction:update', id, data),
        delete: (id: string) => ipcRenderer.invoke('transaction:delete', id),
        list: (filter: TransactionFilter) => ipcRenderer.invoke('transaction:list', filter),
        getById: (id: string) => ipcRenderer.invoke('transaction:getById', id)
    },
    // 预算
    budget: {
        set: (data: SetBudgetDTO) => ipcRenderer.invoke('budget:set', data),
        getMonth: (year: number, month: number) =>
            ipcRenderer.invoke('budget:getMonth', year, month),
        delete: (id: string) => ipcRenderer.invoke('budget:delete', id)
    },
    // 统计
    statistics: {
        getMonthly: (year: number, month: number) =>
            ipcRenderer.invoke('statistics:getMonthly', year, month)
    },
    // 导入
    import: {
        parseFile: (filePath: string, source: 'alipay' | 'wechat') =>
            ipcRenderer.invoke('import:parseFile', filePath, source),
        confirmImport: (data: ImportConfirmDTO) => ipcRenderer.invoke('import:confirmImport', data)
    }
})
```

## 6. 核心业务流程设计

### 6.1 用户切换流程

```
① 用户点击顶栏用户头像 → 展开下拉列表
② 选择目标用户
③ 渲染进程调用 user:switch API
④ 主进程将当前用户 ID 存入内存变量
⑤ 渲染进程清除所有 store 数据
⑥ 重新加载首页数据（按新用户 ID 查询）
```

### 6.2 记账流程

```
① 用户选择类型（支出/收入/转账）
② 选择账户
③ 选择分类（转账时无此步骤）
④ 输入金额
⑤ 可选填写备注
⑥ 点击保存
⑦ 渲染进程调用 transaction:create
⑧ Service 层：
   - 写入 transactions 表
   - 转账场景：自动生成两条流水（一出一入）
   - 更新对应账户的 balance（可选，也可由统计时实时计算）
⑨ 返回保存结果
⑩ 清空金额和备注，保留分类和账户（连续记账）
```

### 6.3 导入流程

```
① 用户选择导入来源（支付宝/微信）
② 调用系统文件选择对话框选择 CSV 文件
③ 主进程解析文件：
   - 读取 CSV → 提取字段（日期、金额、分类、备注等）
   - 将外部分类映射到系统分类
④ 返回解析结果给渲染进程预览：
   - 总条数、成功解析条数、跳过条数
   - 分类映射表（可手动调整）
⑤ 用户确认导入
⑥ Service 层：
   - 逐条写入 transactions 表
   - 自动去重（金额+日期+备注相同视为重复）
⑦ 返回导入结果
```

### 6.4 月度统计计算

```
① 用户切换到统计页或切换月份
② 渲染进程调用 statistics:getMonthly(year, month)
③ Service 层：
   - 查询该月全部非删除流水
   - 计算总支出（type=expense 的金额汇总）
   - 计算总收入（type=income 的金额汇总）
   - 计算结余 = 总收入 - 总支出
   - 统计各分类支出金额和占比
   - 统计每日支出（用于趋势图）
   - 查询该月预算数据 + 计算进度
④ 返回统计结果
⑤ 渲染进程更新图表和卡片
```

### 6.5 预算超支提醒流程

```
① 用户保存一笔支出流水成功后
② Service 层检查该月该分类预算
③ 若超过预算 80% 或 100%：
   - 在保存返回值中带提醒信息
④ 渲染进程收到返回值 → 若有提醒 → 弹出 Arco 通知
```

## 10. 扩展性设计要点

| ------------ | ---------------------------------------------------- |
| 新增功能模块 | IPC 通道 + Service + Store 三层新增，不影响现有结构  |
| 数据库表变更 | Drizzle Kit 生成迁移文件，SQLite 原地升级            |

## 11. 设计要点总结

| 关注点     | 方案                                              |
| ---------- | ------------------------------------------------- |
| 安全性     | 使用 contextBridge，不开启 nodeIntegration        |
| 性能       | 流水查询走索引，月度统计使用 SQL 聚合计算         |
| 数据一致性 | 转账操作使用事务，两条流水同时成功或回滚          |
| 用户体验   | 连续记账设计，保存后保留分类和账户                |
| 数据安全   | 软删除（is_deleted 字段），可扩展回收站功能       |
| 可维护性   | Service 层与 IPC Handler 分离，业务逻辑可独立测试 |
